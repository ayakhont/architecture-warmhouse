# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Система поддерживает переключение между режимами отопления active/inactive с заданным значением температуры.

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система поддерживает добавление и удаление датчиков температуры.
- Каждый датчик имеет уникальный идентификатор, местоположение и текущее значение температуры.
- Система позволяет хранить как информацию о датчике так и значение температуры.

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развертывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

- **Домен: управление устройствами**
  - Поддомен: управление отоплением:
    - контекст: добавление и удаление датчиков температуры
    - контекст: обновление информации о датчиках температуры
- **Домен: мониторинг**
  - Поддомен: мониторинг температуры:
    - контекст: получение и хранение информации с датчиков температуры
    - контекст: получение списка всех датчиков температуры

### **4. Проблемы монолитного решения**

- сложность масштабирования 
- сложность внедрения новых технологий (ограничение в гибкости)
- сложность развертывания (требует остановки всего приложения)
- сложность поддержки и обновления (изменения в одной части могут повлиять на другие части)
